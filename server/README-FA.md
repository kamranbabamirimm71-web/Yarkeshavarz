# زیرساخت اولیه آنلاین یار کشاورز

این پوشه یک **اسکلت فنی قابل توسعه** برای سرور امن است؛ هنوز به سایت اصلی وصل یا در اینترنت مستقر نشده و نباید آن را سیستم فعال فروش دانست.

## چه چیزهایی آماده شده؟

- API پایه برای بررسی وضعیت سرویس و نمایش دو طرح «اقتصادی» و «حرفه‌ای» بدون قیمت ثابت
- جدول‌های کاربران، نشست‌ها، اشتراک‌ها، سهمیه ماهانه، گزارش مصرف هوش مصنوعی و رویدادهای پرداخت در D1
- کنترل سمت سرور برای اشتراک فعال و سهمیه ماهانه چت و تحلیل تصویر
- مسیرهای `/api/ai/chat` و `/api/ai/vision` برای ارائه‌دهنده‌ای با قالب سازگار با OpenAI
- مسیر مدیریتی موقت برای ایجاد حساب آزمایشی و فعال‌سازی دستی اشتراک
- کلید API از متغیر محرمانه سرور خوانده می‌شود و هرگز در فایل‌های فرانت‌اند قرار نمی‌گیرد

## محدودیت‌های مهم — پیش از انتشار عمومی باید تکمیل شوند

1. **ورود کاربران:** مسیر ایجاد کاربر فعلاً فقط برای آزمایش مدیر است. پیش از انتشار باید ورود واقعی با شماره تلفن/ایمیل و OTP یا ارائه‌دهنده احراز هویت معتبر پیاده‌سازی شود. توکن‌های آزمایشی را به کاربران واقعی ندهید.
2. **پرداخت:** اتصال درگاه و وب‌هوک تأییدشده هنوز وجود ندارد. فعال‌سازی دستی فقط برای آزمایش است؛ فروش عمومی را تا پیاده‌سازی تأیید پرداخت، جلوگیری از پرداخت تکراری و رسیدگی به بازپرداخت شروع نکنید.
3. **1xAi:** شرایط منتشرشده این سرویس اشتراک‌گذاری کلید API با اشخاص ثالث برای استفاده تجاری را ممنوع می‌کند. بنابراین پیش از استفاده از یک کلید مشترک برای همه مشتریان، باید مجوز کتبی/شرایط تجاری مجاز از خود 1xAi دریافت شود. تا آن زمان هیچ کلید یا اتصال واقعی در این پروژه تنظیم نشده است.
4. **مدل بینایی:** باید نام یک مدل واقعاً دارای ورودی تصویر را از فهرست فعلی سرویس انتخاب و روی عکس آزمایشی بررسی کرد.
5. **سهمیه و قیمت:** سهمیه‌های فعلی صرفاً مقادیر پیش‌فرض آزمایشی‌اند (اقتصادی: ۱۲۰ پیام و ۱۵ تحلیل تصویر در ماه؛ حرفه‌ای: ۶۰۰ پیام و ۱۰۰ تحلیل تصویر در ماه). این اعداد و قیمت‌ها باید پس از محاسبه هزینه واقعی قابل تنظیم شوند.
6. **حفاظت تولیدی:** پیش از انتشار باید محدودسازی درخواست، کنترل هزینه، پایش خطا، سیاست نگهداری عکس‌ها، شرایط حریم خصوصی و آزمون امنیتی تکمیل شود.

## راه‌اندازی محلی/آزمایشی

نیازمند حساب Cloudflare، Worker و یک پایگاه D1 جدید است. از دیتابیس فعلی/واقعی بدون پشتیبان استفاده نکنید.

1. فایل `schema.sql` را فقط روی یک D1 جدید اجرا کنید.
2. `wrangler.toml.example` را با نام Worker، شناسه D1 و دامنه دقیق سایت تنظیم و با نام `wrangler.toml` ذخیره کنید.
3. متغیرهای محرمانه را با دستورهای محیط Cloudflare تنظیم کنید؛ برای نمونه:
   - `wrangler secret put ADMIN_SECRET`
   - `wrangler secret put AI_API_KEY` (فقط پس از تأیید شرایط تجاری ارائه‌دهنده)
4. `AI_BASE_URL`، `AI_MODEL_TEXT` و `AI_MODEL_VISION` را پس از انتخاب و آزمایش مدل مناسب تنظیم کنید.
5. قبل از اتصال به رابط اصلی، `/health`، احراز هویت، سهمیه، مدل تصویری، هزینه درخواست و خطاهای API را آزمایش کنید.

## مسیرها

- `GET /health`
- `GET /api/plans`
- `GET /api/me` (نیازمند نشست معتبر)
- `POST /api/ai/chat` (اشتراک فعال + سهمیه)
- `POST /api/ai/vision` (اشتراک فعال + سهمیه + تصویر data URL)
- `POST /api/admin/create-user` (موقت، فقط با `X-Admin-Secret`)
- `POST /api/admin/set-subscription` (موقت، فقط با `X-Admin-Secret`)

**مهم:** رابط اصلی برنامه عمداً تغییر نکرده است؛ این کار از خراب‌شدن نسخه‌ای که اکنون داری جلوگیری می‌کند. پس از تعیین میزبانی، ورود و پرداخت، API به‌صورت مرحله‌ای به رابط اصلی وصل می‌شود.
